While initially set to employ OpenAI’s embedding function, we settled on using the local sentence-transformers (all-MiniLM-L6-v2) to save on costs, eliminate external dependence, and still perform effectively enough for our highly technical query sets, even though their vectors have fewer dimensions. As for the vector database, we selected Qdrant because of its ability to filter payloads and allow us to perform hybrid searches, thus allowing more flexibility than Pinecone and Chroma. For our chunks, we chose the recursive character-based approach with an 800 token limit and 100 overlap since we anticipated dealing with tables, which require more precision. Additionally, pdfplumber (pypdf if necessary) was used to maintain table format during extraction. The pipeline can handle CSVs directly, which adds flexibility if the data is pre-processed. Regarding LLM, Haiku will be utilized for heavy extraction tasks, while Sonnet will be used for validation tasks.
